# Data Dictionary

This document defines every variable in the submarine cable dataset and every indicator shown on the dashboard, so that the data is understandable to someone outside the research group.

**Version:** v1
**Dataset:** `submarinecables` table (~695 records)
**Scope:** This version covers the submarine cable dataset and the dashboard indicators. The separate policy and regulation dataset is not yet documented here.


## 1. Dataset variables

### Identity

| Variable | Type | Definition | Coding rules and possible values |
|----------|------|------------|----------------------------------|
| `id` | bigint | Unique record identifier for each cable. | Auto-generated by the database, not user-edited. Positive integers (1, 2, 3, ...). |
| `cable_name` | text | Name of the submarine cable system. | Proper name as commonly published, one cable per row. Example: "2Africa", "Grace Hopper". |

### Physical characteristics

| Variable | Type | Definition | Coding rules and possible values |
|----------|------|------------|----------------------------------|
| `rfs_year` | text | Ready-for-service year: the year the cable entered or is expected to enter service. | Four-digit year stored as text so partial or unknown values are allowed. May be blank. Example: "2025". |
| `length_km` | text | Total cable length in kilometers. | Numeric value stored as text. May be blank if not published. Example: "45000". |
| `status` | text | Operational status of the cable. | Free-text label (not a fixed list); capitalization varies. Example: "In service", "Under construction", "Planned", "Announced". |

### Geography

| Variable | Type | Definition | Coding rules and possible values |
|----------|------|------------|----------------------------------|
| `landing_countries` | text | Countries where the cable makes landfall. | Semicolon-separated list of country names. Example: "Angola; Egypt; France; Kenya; UK". |
| `landing_stations` | text | Specific landing station locations. | Semicolon-separated; each entry formatted "City, Country". Example: "Marseille, France; Mombasa, Kenya". |
| `regions` | text | World regions the cable connects (derived from landing countries). | Semicolon-separated list. Example: "Africa; Asia; Europe; Middle East". |

### Supply side (who built the cable)

| Variable | Type | Definition | Coding rules and possible values |
|----------|------|------------|----------------------------------|
| `suppliers` | text | Company or companies that manufactured and laid the cable. | Semicolon-separated list. Example: "ASN", "SubCom", "NEC". |
| `suppliers_country` | text | Home country of the supplier(s). | Semicolon-separated list. Example: "France", "United States", "China". |
| `chinese_supplier` | text | Flag indicating whether any supplier is Chinese. | Binary flag stored as text: "0" (no) or "1" (yes). Derived from `suppliers_country`. |
| `supplier_bloc` | text | Geopolitical bloc of the cable's supplier(s). | Categorical: Western, Chinese, Mixed, Other, Unknown. Assigned during AI enrichment from `suppliers_country`. See Section 2 for the full rule. |

### Ownership side (who owns the cable)

| Variable | Type | Definition | Coding rules and possible values |
|----------|------|------------|----------------------------------|
| `owners` | text | Entities that own capacity in the cable. | Semicolon-separated list. Example: "Meta; Orange; Vodafone; China Mobile International". |
| `owner_country` | text | Home country of the owner(s). | Semicolon-separated list. Example: "China; US; South Africa; UK". |
| `chinese_owner` | bigint | Flag indicating whether any owner is Chinese. | Binary flag stored as integer: 0 (no) or 1 (yes). Derived from `owner_country`. |
| `owner_bloc` | text | Geopolitical bloc of the cable's owner(s). | Categorical: Western, Chinese, Mixed, Other, Unknown. Same rule as `supplier_bloc`. |

### Regulation and provenance

| Variable | Type | Definition | Coding rules and possible values |
|----------|------|------------|----------------------------------|
| `regulation_notes` | text | Notes on regulatory considerations affecting the cable. | Free text, frequently blank. |
| `source` | text | Source URL(s) the record was drawn from. | Semicolon-separated list of one or more URLs. Recorded by the pipeline during ingestion. |
| `notes` | text | Free-text notes, including verification and correction history. | Free text. Often records corrections with dates and reasons. Example: "CORRECTION Mar 2026: owner name corrected per company FAQ." |

All variables except `id` are populated by AI extraction (Claude) from public web sources located via Perplexity search, except the derived fields (`chinese_supplier`, `chinese_owner`, `supplier_bloc`, `owner_bloc`), which are assigned during processing.


## 2. Dashboard indicators

These are computed from the dataset rather than stored as raw columns.

### Bloc classification

Assigns a supplier or owner to a geopolitical bloc based on their country.

- **Rule:** keyword match on the country string.
  - China: `china`, `chinese`, `prc`, `hong kong`
  - US: `united states`, `usa`, `american`
  - Europe: `france`, `uk`, `germany`, `italy`, `spain`, `netherlands`, and other European countries
  - Japan: `japan`, `nec`
  - India: `india`
- **Combining:** zero matches gives "Other"; one match gives that bloc; two or more gives "Mixed"; a blank country gives "Unknown".
- **On the dashboard,** US, Europe, and Japan are grouped together as "Western".
- **Possible values:** Western, Chinese, Mixed, Other, Unknown.

### chinese_supplier / chinese_owner

Whether a Chinese entity is present on the supply or ownership side. Binary: 0/1.

### Market share by bloc

Share of cables attributed to each supplier or owner bloc. Calculated as the count of cables in a bloc divided by total cables, shown as a percentage and a raw count. Example: "Western 68.9% (479 cables)".

### HHI (concentration)

Herfindahl-Hirschman Index of how concentrated a country's suppliers or owners are across blocs.

- **Formula:** the sum of the squared bloc shares, multiplied by 10,000.
- **Range:** 0 (perfectly spread) to 10,000 (a single bloc holds everything).
- Higher values mean more concentration in one bloc.

### Sovereignty Index

A composite score of how diversified and self-reliant a country's cable connections are. Calculated separately for the supplier and owner perspectives.

- **Formula:** a weighted sum of four parts.
  - **Diversification (40%):** normalized Shannon entropy across blocs (how spread out the country's cables are).
  - **Independence (30%):** the share of the country's cables whose supplier or owner is domestic.
  - **No single-bloc dominance (20%):** 1 minus the largest bloc's share.
  - **Route redundancy (10%):** the number of distinct blocs divided by 5, capped at 1.
- **Range:** 0 to 1.
- **Dashboard bands:** High (> 0.7), Medium (0.5 to 0.6), Low (< 0.5).

The **Independence** component is bloc-neutral: it measures domestic control of infrastructure, not alignment against any particular bloc.


## 3. Notes and items to confirm

**General coding conventions**

- **List fields.** Multi-value fields (`landing_countries`, `suppliers`, `owners`, `owner_country`, `source`, and others) store several values in one text cell, separated by semicolons.
- **Blank vs. zero.** Blank text cells mean "not published / unknown". The Chinese flags use 0 for "no" rather than leaving the cell blank.
- **Numbers stored as text.** `rfs_year` and `length_km` are stored as text so that partial, approximate, or unknown values can be recorded.

**Open items for internal review**

- **Indicator definitions.** The Sovereignty Index, HHI, and Independence definitions were reconstructed by reading the analysis scripts. The research team plans to confirm the exact weights and intent to make them authoritative.
- **Two bloc groupings.** The stored `supplier_bloc` / `owner_bloc` columns use Western / Chinese / Mixed / Other / Unknown (assigned during ingestion), while the sovereignty analysis recomputes a finer grouping (US, Europe, Japan, China, India, Mixed, Other) from the country fields. These should be confirmed as intentional or aligned.
- **Chinese flags.** Confirm whether `chinese_supplier` / `chinese_owner` are set by the same logic as the bloc classification or by a separate rule.
